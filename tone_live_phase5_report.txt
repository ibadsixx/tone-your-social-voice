8. KNOWN FAILURES AND REMAINING LIMITATIONS

Current FAIL items found by real deployed probes:
  1. Migration 005 is absent in the actual Supabase project: the sequence RPC
     next_live_signaling_message_seq does not exist, and authenticated ticket
     issuance returns HTTP 500.
  2. LIVE post creation cannot succeed against the deployed database: the posts
     table lacks host_id, live_session_id, and title.
These are real failures, not mocked-test results.

Historical issues found and fixed during real-browser verification in Phase 4:
  - Early ICE candidates could be applied before remote SDP: fixed by queuing
    and flushing local/remote candidates.
  - Concurrent signaling messages could race setRemoteDescription: fixed with
    a serialized signaling queue.
  - Simultaneous join offers caused glare in three-peer tests: fixed by
    deterministic single-offer initiation with perfect negotiation retained.
  - Local signaling double initially lacked CORS headers and recipient
    routing: fixed in the test double.

Remaining limitations:
  1. Migration 005 was NOT applied. Two Vercel device-login attempts were
     started; neither completed (`vercel whoami` remained "Logged out"), and
     no Supabase token, service-role credential, or SQL endpoint was provided.
     The function/ticket failures above prove the migration is absent, but a
     full columns/constraints/indexes/permissions/history inventory and the
     application of migration 005 remain blocked on authorized access.
  2. Fluid compute could not be verified in Vercel project settings, although
     the deployed WebSocket upgrade succeeds.
  3. Full Vercel build logs and environment-variable values were not read.
     However, Vercel deployment success is confirmed for all relevant commits
     via Vercel's GitHub commit statuses, plus live HTTP/WSS probes and a
     matching deployed frontend asset hash.
  4. Real authenticated two-user and three-user WebSocket flows, ticket
     expiry/reuse, cursor reconnect/replay, and valid message delivery were
     not executed because ticket issuance returns HTTP 500. Unauthorized
     session access WAS executed with real users and correctly returned 403.
  5. Real browser tests used fake media devices and a local signaling double.
     Mute/unmute, camera on/off, participant leave, and host end now PASS in a
     real browser against that double. Physical devices, viewer-role rendering
     against deployed data, reconnection after a network interruption, and
     different networks remain untested in a real browser.
  6. External NAT/STUN traversal and restrictive-network behavior remain
     untested. STUN-only direct host connections were demonstrated locally;
     relay candidates were absent.

Bottom line: Vercel reports successful deployments for the relevant commits,
the deployed signaling WebSocket endpoint upgrades successfully, the deployed
frontend matches the P2P build, and real Chromium two-peer/three-peer WebRTC
with host->host selected candidate pairs PASSES, including mute/unmute, camera
on/off, participant leave and host end in the browser double. Real deployed
probes now show two concrete production FAILs: migration 005 is absent and
LIVE post columns are missing. Authenticated signaling and browser tests
against the deployed Gateway are blocked until those are fixed. This is NOT
production-ready.
