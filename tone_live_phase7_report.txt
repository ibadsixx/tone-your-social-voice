1. GATEWAY IMPLEMENTATION

PASS - Custom SQL/RPC dependency removed from signaling code:
  gateway/src/features/liveSignalingStore.ts no longer calls
  next_live_signaling_message_seq or any Supabase RPC. Remaining .rpc() calls
  elsewhere in the Gateway belong to unrelated older features; the live
  signaling module has none.

PASS - Atomic single-use ticket consumption implemented:
  consumeSignalingTicket() now issues one conditional DELETE ... RETURNING:
    match token_hash
    require consumed_at IS NULL
    require expires_at > now
    optionally require session_id
    delete and return the matching row in one database operation
  This replaces the old select/update design. Two Gateway instances racing on
  the same ticket cannot both receive a row. No SELECT-then-DELETE and no
  custom SQL function is used.

PASS - Database-generated message cursor implemented:
  storeSignalingMessage() omits seq on INSERT/UPSERT. PostgreSQL allocates the
  cursor from a BIGINT GENERATED BY DEFAULT AS IDENTITY column. The
  client-generated id remains the idempotency key. Retries read back the
  original seq instead of calling a sequence function.

PASS - Gateway code paths inspected and updated:
  gateway/src/features/liveSignalingStore.ts
  gateway/api/live/signaling.ts
  all ticket issuance/consumption code
  all signaling message insertion/cursor retrieval code
  LIVE post creation code in gateway/src/api/live.ts
